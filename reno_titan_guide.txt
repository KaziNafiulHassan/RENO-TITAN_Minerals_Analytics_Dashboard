## 3. DATABASE SCHEMA

### Tables to Create:

**3.1 countries**
- Columns: iso3 (PK), name, region, geometry (PostGIS MULTIPOLYGON)
- Purpose: Country reference with geospatial data for maps

**3.2 hs_codes**
- Columns: code (PK), description, commodity_group, material_type
- Purpose: HS-6 code reference for trade tracking
- Seed with: 261400, 282300, 810810, 261510, 282560, 284610, etc.

**3.3 production_data**
- Columns: id, commodity, country_iso3, year, quantity, unit, data_source, notes
- Purpose: Annual production from USGS and BGS
- Unique constraint: (commodity, country_iso3, year, data_source)
- Index on: year, country_iso3

**3.4 trade_data**
- Columns: id, hs_code, reporter_iso3, partner_iso3, flow, year, month, value_usd, quantity, quantity_unit, data_source
- Purpose: Bilateral trade flows
- Unique constraint: (hs_code, reporter_iso3, partner_iso3, flow, year, month, data_source)
- Index on: year, reporter_iso3, partner_iso3, hs_code

**3.5 processing_splits**
- Columns: id, commodity, country_iso3, year, input_material, output_material, split_ratio, source
- Purpose: Material flow coefficients (e.g., 70% ore → pigment, 30% ore → metal)
- Used for Sankey diagram calculations

### Views to Create:

**3.6 mirror_discrepancies**
- Join trade_data exports with imports (reporter ↔ partner swap)
- Calculate: |export_value - import_value| / export_value * 100
- Shows data quality issues in bilateral trade

**3.7 top_routes**
- Aggregate trade_data by (hs_code, origin, destination, year)
- Order by total_value DESC
- Used for flow maps and route rankings

### ETL Tasks:

**4.1 BGS Production Loader**
- Read CSV files (likely wide format: countries as columns, years as rows)
- Melt to long format: (country, year, quantity)
- Map country names to ISO3 codes
- Insert into production_data with data_source='bgs'

**4.2 USGS Production Loader**
- Similar to BGS but check actual CSV structure (may differ)
- Handle missing data for Zr and REE (noted in requirements)
- Insert with data_source='usgs'

**4.3 Trade Data Loader**
- Expected columns: Reporter, Partner, HS_Code, Flow, Year, Value, Quantity
- Map both Reporter and Partner to ISO3
- Standardize flow to lowercase ('import', 'export')
- Zero-pad HS codes to 6 digits
- Insert into trade_data

**4.4 Country ISO Mapping**
- Create dictionary in config.py: {"United States": "USA", "China": "CHN", ...}
- Inspect CSV files for all unique country names
- Manually map any non-standard names

## 5. STREAMLIT APPLICATION MODULES

### Module 1: Production Analysis

**Features**:
- Filter by commodity (titanium_minerals, zircon, ree) and year range
- Display top 10 producers for selected year
- Time series line chart comparing production trends by country
- USGS vs BGS comparison (grouped bar chart, difference table)
- Highlight discrepancies where USGS and BGS differ by >15%

**Key Visualizations**:
- Plotly bar chart (top producers)
- Plotly line chart (trends over time, with line dash for source)
- Dataframe showing absolute and percentage differences

---

### Module 2: Trade QC & Mirror Analysis

**Features**:
- Filter by HS code and year
- **Tab 1: Top Routes** - Bar chart of top 10 export routes by value
- **Tab 2: Mirror Analysis** - Compare exporter-reported vs partner-reported imports
  - Show discrepancies above threshold (e.g., >10%)
  - Grouped bar chart: export value vs import value
  - Table with discrepancy percentages
- **Tab 3: Unit Values** - Calculate price per tonne (value/quantity)
  - Show distribution by country
  - Identify outliers (extremely high/low unit values)

**Key Calculations**:
- Mirror discrepancy % = |export_value - import_value| / export_value * 100
- Unit value = value_usd / quantity

**Key Visualizations**:
- Plotly grouped bar (mirror comparison)
- Plotly box plot (unit value distribution)

---

### Module 3: Geospatial Maps

**Features**:
- **Choropleth map**: Production intensity by country (color scale based on quantity)
- **Flow map**: Origin → Destination arrows showing trade routes
  - Line width proportional to trade value
  - Color by commodity group

**Implementation Options**:
- **Option A**: Folium maps (more interactive, better for flow lines)
- **Option B**: Plotly Choropleth + Scattergeo (easier integration)

**Data Requirements**:
- Need country geometries (GeoJSON) for choropleth
- Calculate lat/lon centroids for origin/destination in flow maps

**Suggested Libraries**:
- `streamlit-folium` for Folium integration
- `geopandas` for geometry handling
- Pre-download Natural Earth country boundaries GeoJSON

---

### Module 4: Material Flow Analysis (Sankey)

**Purpose**: Visualize ore → intermediate → final product transformations

**Example Flow**:
```
Titanium Ore (1000 tonnes)
  ├─→ 70% → TiO₂ Pigment (700 tonnes)
  └─→ 30% → Ti Sponge → Ti Metal (300 tonnes)
```

**Features**:
- Filter by commodity, country, year
- Input: Production data + processing splits table
- Sankey diagram showing mass balance
- Country balance view: Domestic production + imports - exports = Processing capacity

**Key Calculations**:
- Mass balance equation: Input = Output₁ + Output₂ + ... + Losses
- Processing splits from processing_splits table (manual curation based on USGS MIS data)

**Visualization**:
- Plotly Sankey diagram
- Nodes: Raw ore, intermediate products, final products
- Links: Flows with thickness proportional to quantity

## 7. CRITICAL IMPLEMENTATION NOTES

**7.1 Data Cleaning**
- BGS/USGS CSVs may have inconsistent country names → Build comprehensive ISO3 mapping
- Handle null values gracefully (display as "No data" in visualizations)
- USGS missing Zr and REE mine production data (noted in requirements) → Show BGS only for these

**7.2 Performance Optimization**
- Use `@st.cache_data` for database queries that don't change often
- Create database indexes on frequently filtered columns (year, country_iso3, hs_code)
- For large trade datasets, add pagination or limit results

**7.3 User Experience**
- Add loading spinners for slow queries
- Provide "Download CSV" buttons for filtered data
- Include tooltips explaining metrics (e.g., what is mirror analysis?)
- Use expanders for detailed explanations

**7.4 Edge Cases**
- What if mirror data shows import but no corresponding export? → Flag as "one-sided reporting"
- Zero or negative quantities in trade data → Filter out before unit value calculation
- Multiple data sources for same country/year → Show both, let user choose preference
